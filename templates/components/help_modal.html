🏠 Архитектура

Проект работает на Quart (ASGI) с нативным asyncio-циклом. Потоки: FFmpeg → fMP4 HLS → hls.js.

✅ Особенности: асинхронность, 3-stage fallback (GPU→CPU), изоляция кэша, graceful shutdown.

⚙️ Конфигурация

HLS fMP4: hls_segment_type: "fmp4", hls_time: 2, hls_list_size: 6. Флаги: delete_segments+temp_file+program_date_time+split_by_time+append_list.

GPU/CPU: gpu_encoder: "auto" → NVENC → QSV → AMF → libx264. Параметры: video_bitrate: "2500k", gop_size: 30, pix_fmt: "yuv420p".

📹 Камеры

Массив JSON. Обязательные поля: id, main_url. Опционально: sub_url, enabled, comment. ID нельзя менять после создания.

📦 Наборы

Группировка камер в сетки. Поля: name, camera_ids, aspect_ratio (16:9/4:3/9:16), max_columns, max_rows (0=авто).

📝 Примеры RTSP URL

  • Hikvision: rtsp://u:p@ip:554/Streaming/Channels/101 (Main), 102 (Sub)
  • Dahua: rtsp://u:p@ip:554/cam/realmonitor?channel=1&subtype=0
  • ONVIF Generic: rtsp://u:p@ip:554/live.sdp

🛠️ FAQ

СимптомРешение
⏳ Вечное "Подключение..."Проверьте URL в VLC. Увеличьте startup_timeout до 20.
🔴 "All 3 stages failed"Установите "mode":"transcode", "gpu_encoder":"libx264".
⚠️ PermissionErrorДобавьте папку проекта в исключения Windows Defender.
🐌 Задержка >5 секУменьшите hls_time до 2, liveSyncDuration до 0.5.
💡 Для 10+ камер: hls_time: 4, отключите split_by_time. Снижает IOPS диска на ~40%.
