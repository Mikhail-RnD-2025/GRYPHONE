🏠 Архитектура и принципы работы

Проект работает на Quart (ASGI) с нативным asyncio-циклом. Видеопотоки транслируются через FFmpeg → fMP4 HLS и воспроизводятся в браузере через hls.js.

✅ Ключевые особенности: асинхронная обработка, 3-ступенчатый fallback кодировщиков (GPU → GPU alt → CPU), изоляция кэша по камерам, атомарное обновление конфигов, graceful shutdown.

🎥 FFmpeg Global & HLS

Ключевые флаги для fMP4:

  • hls_segment_type: "fmp4" → современный формат, быстрее инициализация, меньше нагрузка на CPU.
  • hls_flags → delete_segments+temp_file+program_date_time+split_by_time+append_list. Не добавляйте low_latency (нестабильно в FFmpeg < 6.0).
  • hls_time → длительность сегмента (2–4 сек). Меньше = ниже задержка, больше = стабильнее сеть.
  • hls_list_size → кол-во сегментов в плейлисте. Оптимально: 5–8.
⚠️ При смене hls_segment_type очистите папку hls_cache вручную!
⚡ Transcode & GPU

Система автоматически определяет доступный энкодер. Логика fallback:

  1. Stage 0: Авто-определение (NVENC → QSV → AMF)
  2. Stage 1: GPU с программным декодированием (если HW-decode не поддерживается)
  3. Stage 2: Чистый CPU (libx264)
ПараметрРекомендация
gpu_encoder"auto" / "h264_nvenc" / "h264_qsv" / "libx264"
video_bitrate"2500k" (1080p), "1500k" (720p)
gop_sizeРавен FPS (30 для 30fps). Критично для HLS!
pix_fmt"yuv420p" (единственный стабильный для браузеров)
📺 HLS.js Player Tuning

Настройки влияют только на браузерный плеер. Баланс между задержкой и буферизацией:

  • maxBufferLength: 3 → буфер в секундах. Меньше = быстрее реакция на обрыв.
  • liveSyncDuration: 0.5 → отставание от реального времени. 0.3–0.8 для камер.
  • backBufferLength: 0 → очищает старые сегменты из памяти браузера.

📹 Управление камерами

Массив объектов в формате JSON. Валидация строгая: недопустимые ID/URL игнорируются.

[
  {
    "id": "cam_01",
    "name": "Парковка Вход",
    "main_url": "rtsp://admin:pass@192.168.1.50:554/stream1",
    "sub_url": "",
    "enabled": true,
    "comment": "Основной поток, 1080p 25fps"
  }
]
  • id → уникален, только латиница/цифры/подчёркивание. Не меняйте после создания (сломает пути к кэшу и архиву).
  • sub_url → если пусто, берётся main_url. Используйте для low-latency sub-потоков.
  • enabled → true/`false`. Отключение мгновенно останавливает FFmpeg-воркер.

📦 Наборы (Layouts)

Группировка камер в сетки для разных сценариев мониторинга.

{
  "default_set": "main_hall",
  "sets": {
    "main_hall": {
      "name": "Главный зал",
      "camera_ids": ["cam_01", "cam_02", "cam_03"],
      "aspect_ratio": "16:9",
      "max_columns": 2,
      "max_rows": 2
    }
  }
}
  • aspect_ratio → 16:9, 4:3, 9:16 (вертикальные камеры).
  • max_rows = 0 → авто-расчёт по количеству камер.
  • Камеры отображаются строго в порядке camera_ids.

📜 Логи FFmpeg

Вкладка собирает stderr каждого процесса FFmpeg и парсит метрики регуляркой:

frame= 125 fps= 25.1 q=-1.0 size=   1534kB time=00:00:05.00 bitrate=2512.3kbits/s
✅ Стабильный fps и растущий time → поток активен.
❌ Connection refused / Invalid data found → камера недоступна или URL неверен.
⚠️ Past duration too large → джиттер камеры. Увеличьте hls_time до 4.

📊 Дашборд

Показывает состояние системы в реальном времени через SSE (/api/stream_status). Обновляется каждые 1 сек.

  • 🟢 Online → FFmpeg активен, HLS плейлист генерируется.
  • 🔴 Error → все 3 стадии запуска FFmpeg провалились.
  • 🔌 Offline/Disabled → камера выключена в конфиге.
  • ⚡/💾/💽 → метрики хоста (требует pip install psutil).

📼 Архив

Автоматическое копирование готовых .m4s сегментов из кэша в пулы хранения.

  • Полы определяются в archive.pools. Каждый пул: id, path, max_size_gb.
  • Файлы переименовываются в {mtime}_{original_name}.m4s для хронологической сортировки.
  • При превышении квоты удаляются самые старые записи + соответствующие init_*.mp4.
  • ⚠️ Архив работает только с hls_segment_type: "fmp4".

🛠️ FAQ & Устранение неполадок

СимптомРешение
⏳ Вечный статус "Подключение..."Проверьте URL в VLC. Увеличьте startup_timeout до 20. Проверьте фаервол.
🔴 "All 3 stages failed"FFmpeg не может декодировать поток. Установите "mode": "transcode" и "gpu_encoder": "libx264" для теста.
⚠️ "PermissionError" в логахWindows Defender блокирует запись. Добавьте папку проекта в исключения антивируса.
🐌 Высокая задержка (>5 сек)Уменьшите hls_time до 2, liveSyncDuration до 0.5. Убедитесь, что браузер не кеширует index.m3u8.
📦 Архив не пишет файлыПроверьте права на папку пула. Убедитесь, что hls_segment_type: "fmp4". Проверьте логи на ошибки ❌ init copy failed.
💡 Совет по производительности: Для 10+ камер используйте hls_time: 4 и отключите hls_flags: split_by_time. Это снизит IOPS диска на 40%.
